## System Requirements

### Hardware (Minimum)

- **CPU:** 2+ cores (4+ recommended)
- **Memory:** 4GB RAM (8GB recommended for 3 nodes)
- **Storage:** 50GB SSD (persistent Docker volumes)
- **Network:** 10 Mbps+ (inter-node gossip traffic)

### Software

- **Docker:** 19.03+ (with BuildKit support)
- **Docker Compose:** 1.25+
- **Bash:** 4.0+
- **jq:** 1.6+ (for parsing JSON responses)
- **curl:** 7.0+ (for manual RPC testing)

### Ports Required (expose on localhost only in devnet)

| Service | Port | Protocol | Notes |
|---------|------|----------|-------|
| pool0 gossip | 30303 | TCP/UDP | P2P discovery |
| pool1 gossip | 30304 | TCP/UDP | P2P discovery |
| pool2 gossip | 30305 | TCP/UDP | P2P discovery |
| pool0 RPC | 9944 | HTTP | JSON-RPC queries |
| pool1 RPC | 9945 | HTTP | JSON-RPC queries |
| pool2 RPC | 9946 | HTTP | JSON-RPC queries |
| pool0 metrics | 9100 | HTTP | Prometheus export |
| pool1 metrics | 9101 | HTTP | Prometheus export |
| pool2 metrics | 9102 | HTTP | Prometheus export |
| Explorer | 5000 | HTTP | Web UI |
| Faucet | 5001 | HTTP | REST API |

## Network Setup

### Quick Start (First Time)

```bash
cd devnet

# 1. Generate genesis (pool keys, epoch nonce)
bash scripts/genesis.sh

# 2. Build Docker image
docker-compose build

# 3. Start all services
docker-compose up -d

# 4. Verify health
docker-compose ps
curl http://localhost:9944/health

# 5. Monitor logs
docker-compose logs -f

# 6. Access services
# - Explorer: http://localhost:5000
# - Faucet: http://localhost:5001
# - Pool0 RPC: http://localhost:9944
```

### Start/Stop Operations

```bash
# Start devnet
docker-compose up -d

# Check status
docker-compose ps

# View logs (all services)
docker-compose logs -f

# View specific service logs
docker-compose logs -f pool0

# Stop all services (keep data)
docker-compose stop

# Resume (data intact)
docker-compose start

# Full shutdown (remove containers, keep volumes)
docker-compose down

# Full reset (remove all data)
docker-compose down --volumes
```

### Multi-Region Devnet (Advanced)

For distributed testing, customize `docker-compose.yml`:

```yaml
services:
  pool0:
    environment:
      - QV_BOOTSTRAP=/bootstrap/bootstrap-region1.peers
    # ... expose on host network or load balancer
```

## Key Management

### Stake Pool Keys

Generated by `genesis.sh` during initialization:

**Location:** `genesis/accounts.toml`

```toml
[[pools]]
pool_name = "Pool0"
vrf_public_key = "abc123..."  # 32-byte X25519 public key
kes_public_key = "def456..."  # Kyber public key (1184 bytes)
pool_id = "hash(vrf_key)"    # Deterministic pool identifier
```

### Key Rotation (Important)

VRF/KES keys should be rotated periodically to maintain forward secrecy:

```bash
# 1. Generate new keys for a pool
docker-compose exec pool0 qv-miner rotate-keys --output /tmp/pool0-new.json

# 2. Review new keys
cat /tmp/pool0-new.json

# 3. Schedule key update (requires chain upgrade or epoch boundary)
# - Edit genesis.toml with new key hashes
# - Redeploy nodes

# 4. Decommission old keys (after successful update)
rm /tmp/pool0-old.json
```

### Faucet Address

The faucet's stealth address is pre-funded at genesis:

**Location:** `genesis/genesis.toml`

```toml
[initial_utxos]
[[initial_utxos]]
value = 100000000000000  # 1M QV in satoshis
stealth_address = "devnet1faucet0000000000000000000000000000000"
```

To rotate faucet address:

```bash
# 1. Generate new stealth address
qv-wallet generate-stealth

# 2. Edit genesis config
vim genesis/genesis.toml
# Update [initial_utxos] faucet address

# 3. Reset devnet
docker-compose down --volumes
docker-compose up -d
```

## Monitoring

### Health Checks

```bash
# Docker health status
docker-compose ps

# RPC endpoint connectivity
curl http://localhost:9944/health | jq

# All services at once
for svc in 9944 9945 9946 5000 5001; do
  echo "Port $svc: $(curl -s http://localhost:$svc/health | jq -r '.status')"
done
```

### Chain Monitoring

```bash
# Current block height
curl -s http://localhost:9944 \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"qv_getTip","params":[],"id":1}' | jq .result

# Monitor block production (1 block per second expected)
watch -n 1 'curl -s http://localhost:9944 \
  -H "Content-Type: application/json" \
  -d "{\"jsonrpc\":\"2.0\",\"method\":\"qv_getTip\",\"params\":[],\"id\":1}" | jq .result.height'

# Mempool size
curl -s http://localhost:9944 \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"qv_getMempoolStatus","params":[],"id":1}' | jq .result

# Node peering status
docker-compose logs pool0 | grep -i "peer\|connected"
```

### Prometheus Metrics

Each node exports Prometheus metrics on port 9100+:

```bash
# Fetch metrics from pool0
curl http://localhost:9100/metrics | grep ^qv_

# Example metrics:
qv_chain_height{node="pool0"} 42
qv_chain_finalized_height{node="pool0"} 10
qv_mempool_size_bytes{node="pool0"} 15234
qv_mempool_transactions{node="pool0"} 3
qv_consensus_slot{node="pool0"} 123
qv_network_peers{node="pool0"} 2

# Monitor with Prometheus + Grafana (optional)
# - Add scrape config for localhost:9100
# - Create dashboard with queries like: qv_chain_height
```

### Log Formats

Logs use structured JSON format for easy parsing:

```json
{
  "timestamp": "2026-04-27T12:34:56Z",
  "level": "INFO",
  "target": "qv_node",
  "message": "Block produced",
  "block_height": 42,
  "block_hash": "abc123...",
  "transactions": 5,
  "duration_ms": 234
}
```

Parse logs programmatically:

```bash
docker-compose logs pool0 | \
  jq -Rs 'split("\n") | .[] | select(length > 0) | fromjson? | select(.level == "ERROR")'
```

## Common Issues and Recovery

### Issue: Nodes Won't Sync (Different Heights)

**Symptoms:**
```bash
$ docker-compose ps
pool0    height 50
pool1    height 30
pool2    height 45
```

**Root Causes:**
1. P2P network disconnected
2. Gossip topics misconfigured
3. Block validation rejecting blocks
4. Storage corruption

**Recovery:**

```bash
# 1. Verify network connectivity
docker-compose exec pool0 ping pool1
docker-compose exec pool1 ping pool0

# 2. Check for P2P errors
docker-compose logs pool1 | grep -i "network\|peer\|error" | tail -20

# 3. Restart slow node
docker-compose restart pool1

# 4. Wait 30 seconds for sync
sleep 30
docker-compose ps

# 5. If still lagging, full reset of that node
docker-compose stop pool1
docker volume rm devnet_pool1_data  # or use --volumes
docker-compose up -d pool1

# 6. Verify convergence
watch -n 2 'docker-compose ps'
```

### Issue: Mempool Stuck (Transactions Not Advancing)

**Symptoms:**
```bash
$ curl http://localhost:9944/rpc | jq '.result.mempool_size'
1234  # Not decreasing over time
```

**Recovery:**

```bash
# 1. Check if blocks are being produced
curl -s http://localhost:9944 ... | jq .result.height
# Should increment every 1-2 seconds

# 2. Check for mempool validation errors
docker-compose logs pool0 | grep -i "mempool\|validation\|error" | tail -30

# 3. Restart mempool service (kills pending transactions)
docker-compose exec pool0 qv-node --flush-mempool

# 4. If persists, restart node
docker-compose restart pool0

# 5. Full reset as last resort
docker-compose down --volumes
docker-compose up -d
```

### Issue: RPC Endpoint Returns 502/503 (Service Unavailable)

**Symptoms:**
```bash
$ curl http://localhost:9944/health
curl: (7) Failed to connect to localhost port 9944: Connection refused
```

**Recovery:**

```bash
# 1. Check if container is running
docker-compose ps pool0

# 2. View startup logs
docker-compose logs pool0 | head -100

# 3. Check RPC port binding
docker-compose exec pool0 netstat -tlnp | grep 9944

# 4. Restart RPC service
docker-compose restart pool0

# 5. If container crashes, check Dockerfile/entrypoint
docker-compose build --no-cache

# 6. Increase log verbosity for diagnosis
docker-compose env | grep LOG_LEVEL
# Edit docker-compose.yml, change --log-level=info to debug
docker-compose down
docker-compose up -d
```

### Issue: Faucet Drips Failing ("RPC request failed")

**Symptoms:**
```bash
$ curl http://localhost:5001/drip?address=devnet1alice...
{"error":"RPC request failed"}
```

**Recovery:**

```bash
# 1. Verify faucet service is up
docker-compose ps faucet
curl http://localhost:5001/health

# 2. Check faucet logs
docker-compose logs faucet | tail -50

# 3. Verify RPC endpoint is reachable from faucet container
docker-compose exec faucet curl http://pool0:9944/health

# 4. Check network connectivity
docker-compose exec faucet ping pool0

# 5. Restart faucet
docker-compose restart faucet

# 6. Check faucet UTXO still exists
curl -s http://localhost:9944 ... | jq '.result | select(.tx_id == "faucet_utxo_id")'

# 7. If faucet UTXO consumed, regenerate genesis
bash scripts/genesis.sh
docker-compose down --volumes
docker-compose up -d
```

### Issue: High Memory/CPU Usage

**Symptoms:**
```bash
$ docker stats
CONTAINER   MEM USAGE
pool0       2.5GB / 4GB
pool1       1.8GB / 4GB
```

**Causes & Fixes:**

```bash
# 1. Check for memory leaks (long-running chain)
docker-compose ps
# If running >24h with monotonic growth, likely leak

# 2. Reduce block production rate
# Edit docker-compose.yml
# Change SLOT_DURATION_MS from 1000 to 2000 (slower blocks)

# 3. Check for unbounded data structures (large UTXO set)
docker-compose logs pool0 | grep -i "utxo\|cache" | head -10

# 4. Reduce number of nodes (if testing only 1)
docker-compose stop pool1 pool2

# 5. Clean up old block data
docker-compose down --volumes
docker-compose up -d

# 6. Monitor memory over time
docker stats --no-stream > /tmp/stats-$(date +%s).txt
```

## Performance Tuning

### Block Production Rate

Default: 1 block per second (1000 ms slot duration)

To adjust for your hardware:

```yaml
# In docker-compose.yml
services:
  pool0:
    command:
      - qv-node
      - --slot-duration-ms=2000  # Slower (2s slots)
      # or
      - --slot-duration-ms=500   # Faster (0.5s slots)
```

### Network Gossip Tuning

For high-latency networks, adjust gossip parameters:

```toml
# In genesis/genesis.toml or node config
[network]
gossip_heartbeat_interval_ms = 1000  # How often to send peer updates
gossip_lazy_push_size = 10            # Batch size for lazy propagation
gossip_max_ihave_messages = 100       # Max IHAVE messages per heartbeat
```

### Storage Optimization

RocksDB tuning for faster queries:

```bash
# Increase block cache size (more RAM, faster reads)
docker-compose exec pool0 qv-node --rocksdb-block-cache-size-mb=512

# Compress old data (trades CPU for disk space)
docker-compose exec pool0 qv-node --rocksdb-compress=lz4
```

### CPU Pinning

Pin node processes to specific cores (Linux only):

```bash
# Run pool0 on cores 0-1, pool1 on cores 2-3, pool2 on cores 4-5
docker-compose exec pool0 taskset -c 0-1 qv-node ...
docker-compose exec pool1 taskset -c 2-3 qv-node ...
docker-compose exec pool2 taskset -c 4-5 qv-node ...
```

## Security Considerations

### Network Security (Devnet Only!)

The devnet exposes RPC endpoints on localhost without authentication:

```bash
# DO NOT expose devnet to untrusted networks
# Ensure firewall blocks ports 9944-9946, 30303-30305 from WAN

# If you must expose:
# 1. Run behind reverse proxy with authentication (nginx + OAuth2)
# 2. Use TLS/HTTPS
# 3. Rate limit RPC endpoints
# 4. Implement IP whitelisting
```

### Key Backup

**Important:** Back up your stake pool keys!

```bash
# Backup genesis directory
tar -czf /secure/location/genesis-backup-$(date +%Y%m%d).tar.gz devnet/genesis/

# Secure access
chmod 700 /secure/location/
```

### Restart Recovery (Crash-Safe)

The devnet is crash-safe due to Docker volume persistence:

```bash
# Unclean shutdown (e.g., `docker kill`)
docker-compose down --force

# Volumes remain, restart normally
docker-compose up -d

# Chain state is recovered from persisted blocks
```

### Audit Logging

Track all governance/key operations:

```bash
# Enable audit log (write to file)
docker-compose exec pool0 qv-node --audit-log=/data/pool0/audit.log

# Review operations
docker-compose exec pool0 tail -f /data/pool0/audit.log

# Parse for security events
docker-compose logs pool0 | jq 'select(.event == "UNAUTHORIZED_RPC_CALL")'
```
